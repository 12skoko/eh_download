# 主界面 界面设计风格

本文记录 主界面（`/`）的界面美学与设计取舍，供后续修改时保持一致。只讲“看起来应该怎样、为什么”，不涉及实现细节。

## 一、气质

一句话：**安静的纸面工作台**。

- 这是长期挂着看的运维控制台，不是展示页。界面要让人一眼看到“哪里需要我处理”，其余信息退到背景里。
- 底色是偏暖的米白，像宣纸；深色主题是偏暖的墨黑，不用冷蓝灰。两套主题分别叫「宣」和「墨」，默认跟随系统。
- 克制优先：少色、少线、少阴影、少动画。能用留白和字重区分的，就不用颜色和边框。
- 不用渐变、玻璃拟态、大面积插画、emoji 图标，也不用营销式的大标题和口号。

## 二、色彩

### 品牌色

- **靛青**（浅 `#2e4a7d` / 深 `#93acdd`）：唯一的主操作色，用于主按钮、选中态、链接悬停、当前页码、焦点环。一屏里靛青实心按钮最好只有一个。
- **朱砂**（浅 `#b3371e` / 深 `#e2694f`）：像印章，只用于品牌标识、错误、需要人工处理的异常和不可逆操作（终止、删除、强制操作）。不能当装饰色。

### 语义色

| 语义 | 浅色 | 含义 |
|---|---|---|
| ok 绿 | `#2a7352` | 完成、健康、可调度 |
| run 青蓝 | `#1d6a86` | 正在进行 |
| warn 琥珀 | `#9a5f0a` | 等待、暂停、需要留意 |
| danger 朱砂 | `#b3371e` | 异常、需要人工处理、冷却受阻 |
| special 靛青 | `#2e4a7d` | 进入特殊处理 |
| muted 灰 | `#5e5950` | 已结束、被排除、不再参与流程 |

每种颜色都按三档使用：文字/图标用本色，底色用极淡的 soft 色，边框用介于两者之间的 line 色。不要用饱和的实心色块表达状态。

### 上色原则

- **只给需要关注的东西上色。** 大多数状态用正文色或灰色，颜色留给“要我做点什么”的情况。全屏五颜六色等于没有重点。
- **同一个状态在所有地方同一种颜色。** 档案状态有唯一的配色表，列表胶囊、筛选项、下拉框、流程条都按它来，不能这里黄那里灰。
- **不同语义的状态不共用颜色逻辑。** 档案状态、任务运行状态、调度器状态是三套东西，各有各的配色，不要拿“运行中”的蓝去表示档案状态。
- **概览可以更克制。** 概览流水线只突出观察等待（琥珀）、人工复核和已隔离（朱砂），其余数字不上色，数量为零的显示淡灰。

### 档案状态配色（定稿）

- 青蓝（进行中）：下载中、校验中、准备中、上传中
- 靛青（特殊）：特殊处理中
- 琥珀（等待）：观察等待、已发现、等待下载、已下载、等待冲突改名、等待上传、已上传、等待取消、已过时、等待强制删除
- 绿（完成）：已完成
- 朱砂（异常）：人工复核、已隔离
- 灰（出局）：不可用、已删除、筛选排除、已跳过、下载受阻、已取消

### 模块调度状态配色

- 可调度：白底，左侧细绿条
- 运行中：青蓝底青蓝字
- 冷却中：朱砂底朱砂字
- 已暂停：琥珀底琥珀字，虚线边框（暗示“临时”）
- 已禁用：灰实底灰字，实线边框；禁用优先于其他状态

## 三、字体与排版

- 正文用 Geist，中文回落到苹方、微软雅黑、思源黑体。ID、错误码、文件名、路径、URL、时间戳用 Geist Mono，让人一眼分辨“这是机器给的值”。
- 字号偏小而紧凑（11.5–15px 为主），信息密度高，但行高留足。层级主要靠字重和颜色深浅（正文 / 次要 / 弱化 / 极弱四级灰），少用字号跳变。
- 大数字（概览计数、关键指标）用大号等宽数字，配一行小号灰色说明。
- 数字一律等宽对齐，表格里数字右对齐。

## 四、形状、线条与层次

- 圆角小而统一（5 / 7 / 11 / 14px 四档）。模块卡片用更方的 4px 圆角，和圆润的状态胶囊区分开。
- 分隔优先用一像素细线和底色深浅，不用粗边框。阴影非常淡，只用来表示“浮起”（弹层、对话框、通知）。
- 层次从后到前：页面底色 → 侧栏（略深）→ 卡片面（略浅）→ 浮层（带阴影）。下陷区域（输入框底、分段控件底、模块底带）比卡片面略深。
- 深色主题不是简单反色：底色、线条、语义色都单独调过，语义色在深色下提亮、降饱和，避免刺眼。

## 五、布局

- 左侧固定导航，顺序为：概览、档案、待处理、工作流｜事件、日志｜配置、系统。底部是旧版入口、主题切换和退出。
- 顶栏只放面包屑、全局搜索（Ctrl K）和调度器状态胶囊。
- **概览**：最上面是“需要关注”的提醒卡，下面是流水线。流水线分两行：上面一行是档案，按阶段排成文字计数；下面一行是模块，用方角卡片放在浅灰底带里。行首标注“档案 / 模块”。旁路状态（异常与旁路、删除队列）单独放在下方。
- **列表 + 详情**：档案和待处理采用左列表、右详情侧栏。侧栏可以拖动调宽，记住用户偏好，双击恢复默认。列表变窄时自动隐藏次要列，保证标题可读。
- 列表只放判断所需的最少信息。档案列表为：档案（标题 + 等宽 ID）、状态、当前错误、更新时间。其他信息看详情。
- 每页条数放在左下角分页器旁边，不放在顶部工具栏，避免和筛选、侧栏挤在一起。
- 待处理的左侧分面先“发生环节”，后“错误类型”。
- 窄屏下侧栏变为浮层，导航收进菜单，流水线阶段上下排列。

## 六、交互气质

- **安静的实时性**：活动区和工作流面板会自动刷新，但不打扰人。打开对话框、弹层、拖动侧栏，或者正在面板里填写表单时，都暂停刷新，不冲掉用户的输入。
- **筛选即生效**：筛选不需要“提交”按钮，选中即刷新列表，并写进地址栏，可以分享和后退。
- **危险操作要停一下**：不可逆操作用对话框确认，写清会发生什么、什么会保留，并要求勾选确认；按钮用朱砂色。普通操作不弹确认。
- **反馈就近**：表单错误显示在表单内，操作结果用右下角小通知，不用整页跳转。
- 动画只做必要的出现过渡（弹层、对话框轻微上浮），时长短；系统开启“减少动态效果”时全部关闭。
- 键盘友好：J/K 上下切换、Esc 关闭、Ctrl K 搜索，焦点始终可见。

## 七、文案

- 中文，短句，先说结果或后果，再说原因。不用感叹号，不写宣传语。
- 状态和操作用固定的中文名称（如“人工复核”“恢复调度”“解除冷却”），全站统一。
- 技术标识（状态码、错误码、字段名、模块名）原样保留，用等宽字体显示，必要时在旁边附中文。
- 说明文字放在灰色小字里，只写会影响判断的内容（“已采集档案和检查点会保留”），不写显而易见的话。

## 八、入口与备用界面

主界面使用 `/`，V1 备用界面使用 `/v1/`。两套界面提供对应页面的切换入口，共用认证、数据库、业务服务和 API。主界面的概览、状态语义与交互以上述规范为准。

## 九、修改时的自检

- 这一处新颜色是不是在表达“需要关注”？如果不是，去掉。
- 同一个状态，在列表、筛选、详情、概览里颜色一致吗？
- 浅色、深色、窄屏三种情况下都看过了吗？
- 有没有新增和现有组件长得差不多却不一样的东西？能复用就复用。
- 删除或隐藏的信息，在详情或别处还能找到吗？
